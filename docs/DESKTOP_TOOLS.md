# Desktop tools (preview)

- **MenuBar**: set groups to an array of unique group IDs, labels, optional disabled flags and command items (value, label, disabled). Composes MenuButton and MenuItem. Only one popup is open at a time; each menu retains its existing keyboard navigation and overlay behavior. Emits cu-action with group, value and label. This is a group of menu buttons, not a full ARIA menubar; left/right traversal between menus, nested submenus, shortcuts and checked actions are not implemented.
- **Ribbon**: assign tabs with unique IDs, labels, disabled flags and groups with commands. Uses Tabs and CommandBar, including adaptive overflow. The active property selects an enabled tab by ID. Emits cu-change (value/index) and cu-action (tab/group/value/label). Disabled prevents commands, not tab navigation. No native Office-style customization or collapsed ribbon mode yet.
- **Terminal**: assign lines as strings or {text,kind} records. append(text,kind) adds output, clear() removes it, submit(command) emits a cu-action request with action:"submit" and value. Keeps up to max-lines (default 1000, maximum 10000) and 100 command-history entries; Up/Down navigate history, Enter submits. VirtualList displays output; selecting a line shows full text below. It does not execute shell commands, emulate ANSI/VT escape sequences or connect to a PTY. The demo implements only help, version and echo in local JavaScript. Consumers must authorize and validate commands in any external execution layer.
- **WindowManager**: use direct cu-window-pane children with unique data-window-id attributes and title. The active property selects an open pane. activateWindow(id), closeWindow(id), reopenWindow(id) return booleans. Closed/inactive panes stay mounted; their content and state persist. Duplicate or missing pane IDs are hidden. A DockLayout supplies a resizable navigator. cu-change reports selection; cu-action reports close/reopen. No native OS windows, floating-window drag/resize, z-index stacking or persistent layout storage yet.

All use shared UI components and tokens, standalone exports and React wrappers; Vue/Svelte can bind properties to registered custom elements. Browser and accessibility acceptance is still required.
