# Designer workspace tools (preview)

- **MediaLibrary** accepts FileExplorer entries with optional mediaType (image/audio/video), src and video poster. The file tree is validated by the shared file normalization. Selecting a file shows its image or media preview; images share ImageGallery navigation. Audio/video uses native controls through MediaPlayer, and playback pauses when switching to another source or non-media preview. cu-select reports the selected descriptor; cu-action forwards file/image requests with section metadata; cu-navigate reports folder selection; cu-media reports playback events. The application supplies trusted media URLs and implements file operations. No upload transport, thumbnail generation, automatic MIME detection or file persistence.
- **DashboardDesigner** accepts up to 24 unique chart widgets, each with config and items from existing chart helpers. Add, select, remove, and edit widgets using ChartEditor; DashboardShell displays responsive chart previews. readonly prevents changes. cu-change reports action, id and widgets; cu-select reports selected ID. No drag resizing, widget positioning, external data bindings or dashboard persistence.
- **FormDesigner** accepts up to 50 unique field IDs and unique nonempty names. Supports text, email, number, textarea and checkbox, with label, required and default value. Rejects field names reserved by native form APIs. Reuses PropertyInspector, CuForm and form-associated controls. Test submit invokes native validation and emits cu-submit with local FormData converted to an object; no network submission. Unchecked checkbox fields are omitted; checked checkboxes use the standard form value. Preview input edits are not schema edits and reset when the schema is rebuilt. readonly locks schema editing but allows testing the form. No conditional fields, drag reordering, nested fields or code generation.
- **SchemaEditor** edits a deliberately limited JSON Schema object with up to 100 top-level properties, each with one supported type (string/number/integer/boolean/array/object/null), optional description, and root required list. Invalid or unsupported properties and unknown required names are dropped. Uses a null-prototype property dictionary to handle special property names safely. Output is displayed through JsonViewer. Add, remove, select, edit and readonly are supported. This is not a general JSON Schema parser, validator or lossless editor: nested schemas, constraints, references and composition keywords are not preserved.

All four are preview Web Components. Standalone exports, React mappings and Playground demos are included. Browser and accessibility acceptance remains required.
