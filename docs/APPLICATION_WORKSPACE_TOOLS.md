# Application workspace tools (preview)

- **ShortcutSettings** composes SettingsPage and KeyboardShortcutEditor. Supply items and defaults using the existing shortcut item schema. Reset matches default shortcuts by ID, retains locked assignments and unknown items, and rejects the entire reset if the result contains duplicate nonempty shortcuts. cu-change reports action (update/reset) and items. It edits settings, not OS shortcut registrations.
- **DocumentWorkspace** composes WindowManager with two persistent panes, PDFViewer and MarkdownEditor. Use pages for pre-rendered images or document for an application-owned renderer (one source at a time), page for page selection, notes for Markdown source, and active for document/notes. readonly locks notes only. The panes remain mounted during navigation. Events include section (document/notes/workspace) so the host can route updates. No PDF decoding, annotation anchoring, file upload or persistence; the host owns resources.
- **DataInspector** accepts JSON-serializable record objects. Non-records and unserializable entries are skipped; records are cloned through JSON serialization (therefore undefined fields and non-JSON values are not preserved). Up to 50 distinct nonempty top-level fields are exposed as columns and QueryBuilder fields, with synthetic column keys and row IDs (1-based source position), avoiding collisions with record IDs. The query uses existing AND/OR filter semantics and QueryBuilder-supported operators. visibleRows counts query-matched records before additional DataTable header filtering. Use the row context menu's Inspect record action to see the full JSON, or call inspectRecord with the synthetic ID of a currently filtered record. cu-select reports the original cloned row; cu-input/change report query and count. Not a remote data client, database query engine or JSON editor.
- **APIExplorer** exposes request (method, absolute HTTP(S) URL, body), response (status, body, contentType), and loading/disabled. Validates URL syntax, rejects embedded URL credentials and nonempty GET/HEAD bodies. submit emits cu-action with action:"request" and a request descriptor; the application implements transport, security policy, cancellation, credentials and response assignment. It never executes requests itself. Raw and JSON response tabs reuse CodeBlock and JsonViewer; JSON appears only for parseable responses. No header/auth editor, history, streaming, response-size limit or OpenAPI generation. Never pass untrusted request descriptors to privileged transport without validation/authorization. The Playground uses local mock responses only.

All four components have standalone exports, React adapters, contracts and demos. Browser and accessibility acceptance remains required.
