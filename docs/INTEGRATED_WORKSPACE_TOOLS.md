# Integrated workspace tools (preview)

- **DatabaseExplorer** accepts up to 100 unique table descriptors (id, label, schema, rows) and groups them by schema using TreeView. DataInspector supplies AND/OR queries, table filtering, pagination and record JSON inspection. Switching tables restores the saved QueryBuilder filter for each table and resets column filters/visibility because column keys are synthetic. selected and query are configurable. cu-select distinguishes table selection (tableId, value) from record inspection (tableId, recordId, row); cu-input/change include tableId and query. Local snapshots only: no SQL, database connection, credentials, remote pagination or writes.
- **ApplicationShell** combines AppShell, Sidebar, MenuBar and CommandPalette. Define sections with unique id/label/disabled, menu groups, and palette commands. Direct slotted elements with matching data-section are shown for the active section; other panels stay mounted. Ungrouped content remains visible. Disabled sections cannot be selected. cu-change reports section selection; cu-action reports a menu/palette command and source. Ctrl/Meta+K works when focus is within the shell. No URL routing, history management, authentication or command execution.
- **ReportBuilder** uses QueryBuilder and PivotTable to filter and aggregate local record snapshots. Supply rows, query and pivot config; chart-type selects bar/line. ChartContainer displays finite group totals derived from the pivot result (not separately editable). Export emits cu-action with action:"export" and a report snapshot (config, query, chartType, result). The host implements actual export, formatting and persistence. Existing PivotTable limits apply; up to 50 fields are discovered. No report scheduling, PDF/Excel output or remote query execution.
- **AutomationDesigner** composes NodeEditor and WorkflowEditor in tabs. The graph is normalized using NodeEditor rules, then checked for directed cycles with a topological sort. A valid nonempty acyclic normalized graph enables Request run; it emits action:"run-request", the value and a dependency-respecting node order. Independent implementation tasks are not execution nodes and do not affect graph validity. Disconnected acyclic components are allowed. readonly disables edits and run requests. No execution engine, scheduler, retries, credentials or external system actions; host must validate and authorize any requested run.

All four are preview components, use existing UI and design tokens, and have standalone exports, React adapters and Playground demos. Browser and accessibility acceptance remains required.
